# Close Record: Decision Records That Are Quick to Review and Hide No Gaps

none

## Key Decisions

- **The new format takes the existing template name; the old one becomes `decision-record-template-v1.md` and joins the seeded set.** Every stage and anchor already names `decision-record-template.md`, so the default drafting path gets the new format and only the rare old-format revision names a second file. Refuted viable alternative: give the new format a new name and leave the old name on the old template — it spares adopters a re-seed, but leaves every new record drafted from the old file by default.
- **A seeded template with no `## Guarantees` section stops `/nxs.decision-record`, naming the re-seed as the remedy.** Seeding never overwrites, so an adopter's tuned copy stays old, and drafting new-format content into it would file a record in neither format. Refuted viable alternative: draft from the master shipped in the release — needs no lead action, but silently ignores a project's tuned template.
- **The release is marked breaking.** A repository seeded before 0.74.0 finds `/nxs.decision-record` stopping until the lead re-seeds, so the changelog says "Breaking" and the release-notes context sets `breakingChange: true`. Refuted viable alternative: none.
- **The refuted-alternative line is written by template guidance, not a standing slot.** D6 requires every optional field present as `none`, and `nxs-razor` §9 forbids a standing slot or placeholder for the alternative in any template; a guidance comment satisfies both. Refuted viable alternative: a standing `{{ALTERNATIVE}}` line as in the trial template — it contradicts §9 and the conformance test that pins it.
- **Cut IDs reach the derive step as an explicit `--cut G3,R2` list.** The stage already knows what the reviewer cut, and an explicit list is deterministic; derive stops naming every line that still cites a listed ID as a whole token, and writes nothing. Refuted viable alternative: detect cut IDs as gaps in the G/R numbering — needs no flag, but a gap left by an earlier revision would read as a fresh cut.
- **`none`-field removal is a generic rule over any derived body, not a record-shaped one.** G10 says no `none` field reaches a filed body, and no epic, close or story template writes such a line, so the generic rule costs epics nothing; `survivingTokens` reports one as `none-field`. Refuted viable alternative: remove them only inside a record's `#### D<n>` entries — narrower, but it makes derive format-aware and misses a `none` field written elsewhere.
- **`readRecord` returns one flat shape, with guarantees and invariants as separate lists and the absent one empty.** One shape serialises directly for the read-only command, and leaving a draft in neither format on the old heading path keeps every old-format checkpoint result unchanged. Refuted viable alternative: a discriminated union per format — stricter in TypeScript, but every caller then branches before it can read the risks and decisions both formats share.
- **The section reader is a separate projection over `readRecord`, not an extension of it.** `recordSections` maps raw lines into named parts (decision, why, refuted alternatives, trade-off, delivered by, guarantee IDs; guarantee group and cited decisions; risk severity; concept-change page/old/new), and `nexus record-sections --body` prints it as JSON. The checkpoint needs the raw lines and their exact text for cuts and frozen marks while the later stages need values by name, so one reading serves both without changing the checkpoint's shape. Refuted viable alternative: extend `RecordReading` itself with the named fields — one type, but every checkpoint caller then carries fields it never reads and a change for one reader risks the other.
- **The reader prints no prose section text for close's baseline.** `record-sections` lists parts only; `/nxs.close` reads How it works and the Mechanism from the body as prose, because the reader's job is the lists a stage can drop a line from, and a prose section cannot lose a line that way. Refuted viable alternative: include `howItWorks` and `mechanism` text in the JSON — one fewer place to look, but it duplicates the body and adds fields no check reads.
- **The neither-format block is opt-in via `razor-check --source --record`.** The checker cannot tell a record draft from an epic draft by content, and an epic draft always reads as neither, so `/nxs.decision-record` passes `--record` at its draft check. Refuted viable alternative: infer "record" from a `# Decision Record:` heading — no flag, but a hand-edited heading would silently skip the check it exists for.
- **Distill's additions were paid for inside its recorded load ceiling.** The base stage condensed the Phase 3 Sources paragraph and the Phase 0 old-contract/no-record items that restated each other, rather than raising the ceiling, because the ceiling record requires `replaces > bytes` and is designed only to go down. Refuted viable alternative: move the format rules into a new distill contract skill — it keeps the base stage small, but the rules apply to every ordinary drain, which the contract model reserves for no contract.
- **`nexus record-amendments` reads a bare `#N` against the resolved epic repository and takes no `--epic` flag.** The record is filed as a sub-issue of the epic, so under the issue-reference rule a bare number in its body resolves against the epic's repository, and a story in another repository is already written qualified. Refuted viable alternative: take `--epic <N>` and read every other number against `story-repo` — it guesses right for an unqualified story in a split workspace, but contradicts the reference rule the record body is written under.
- **The amendment check fails closed on an unreadable commitment line.** A non-`none` "Epic commitment affected" line that does not parse as `<issue>. Old: "…". New: "…". Status: <status>.` exits 1 naming the decision and the line, and nothing is fetched; an `unresolved` line may omit the wording and is reported unchecked. An unchecked commitment must not read as a checked one, and the stage has no result to write for a line it cannot parse. Refuted viable alternative: report the line in the JSON and exit 0, leaving it to the cross-reference block — output stays complete, but nothing stops a malformed commitment reaching the cut list.
- **The pure half of the amendment check lives in scope-razor, the `gh` half in portable-tools.** `@nexus/scope-razor/amendments` reads commitments through `readRecord` and matches wording; `record-amendments.ts` resolves the repository and fetches through an injected `Runner` with an injectable clock, because scope-razor has no process seam and the verb module can take a fake runner in its spec. Refuted viable alternative: reuse `fetchRecord` from record-digest for the fetch — one fewer `gh` call site, but its diagnostics name a "record issue" and it hashes a body nobody reads here.
- **The story count for the multi-story checks comes from the resolved `epic.md` via `--epic <path>`.** `epic.md` has one deterministic producer, while `source.md` is assembled by the model and may hold story bodies with no story headings, which would read as a one-story epic and silently skip the check. Refuted viable alternative: `--stories <n>` — explicit, but the model counts and a wrong count passes silently.
- **A decision listed under both "Resolve before approval" and "Choices with trade-offs" blocks.** G5 says it appears exactly once; two copies are how the trial's #786 lost a trade-off when an item moved groups, because one copy goes stale. Refuted viable alternative: accept the duplicate as listed — it never blocks a correct draft, but lets the stale copy stand.
- **G13's wording check reuses the amendment reader, so an unquoted old wording blocks.** Each commitment is read through `commitmentsIn`; a line it cannot read, or one giving no quoted Old or New (including an `unresolved` line that omits them), blocks whatever the brief says, and an addition passes with `Old: ""`. One reader means the checkpoint's two steps agree on what "the exact wording" is, and the acceptance criterion is unconditional. Refuted viable alternative: accept prose such as `Old: no criterion` as an addition — it passes the trial records, but the amendment check cannot read that line.
- **"Listed" means a whole-token ID anywhere in the group's block.** An ID counts as listed when it appears as a whole token on any line (sub-bullets included, labels stripped) between the group's bold line and the next bold line or heading, because Resolve entries cite IDs inside prose such as "(D2, D9)". Refuted viable alternative: match only the leading `D<n>.` of a Choices item — stricter for Choices, but two rules for one word "listed".
- **An unnumbered guarantee or decision blocks on its own.** Every cross-reference check matches by ID, so an unnumbered item skipped them all and could not be listed under "Resolve before approval" either. Refuted viable alternative: block an unnumbered item only when it would fail a check if numbered — that re-implements every check a second time, by text, to reach the same fix (add the ID).
- **The `record-new` fixture's pending change became `amended`.** Its pending change sat under Choices rather than Resolve, which is exactly the gap the cross-reference check blocks, and the fixture is used as a passing draft; amending keeps every line number other specs pin. Refuted viable alternative: move D2 into "Resolve before approval" — also valid, but it shifts the fixture's lines.

## Deviation Rationale

All six deviate from decision record #794.

- **A second seeded template (`decision-record-template-v1.md`) where the record's Mechanism names one seeded template** (#794): every stage and anchor already names the existing file, so the default path had to carry the new format, leaving only the rare old-format revision to name a new file. G11 requires an old-format revision to keep its format; the record did not say which file supplies it.
- **`/nxs.decision-record` hard-stops on a seeded template with no `## Guarantees` section, and the release is marked breaking** (#794): the record's Mechanism assumes the seeded template matches the format the stage drafts, but seeding never overwrites, so an adopter's copy stays old. Drafting new-format content into an old copy would file a record in neither format, which G20 blocks at the checkpoint anyway — stopping at the template is the earlier, nameable failure.
- **`none`-field removal in derive applies to every derived body, not only records** (#794): G10 is written about a record's filed body, but no epic, close or story template writes a `- **Field:** none` line, so the generic rule costs those bodies nothing while keeping derive format-blind. A record-only rule would have made derive format-aware and missed a `none` field written outside a `#### D<n>` entry.
- **An unnumbered guarantee or decision blocks on its own, beyond G7 and #792's acceptance criteria** (#794): G7 blocks an unlabelled guarantee or risk and G12–G14 match by ID, so an unnumbered item silently skipped every one of them and could not be listed under "Resolve before approval" either. The record's checks assume IDs exist; nothing in it made their absence blocking.
- **`utils/implement-epic.sh`'s GOAL prompt was reworked and a `/nxs.distill` codex substitution added, with no story covering it** (#794): the script drives the implementation agents against a record, and its prompt named the retired "invariants" vocabulary. Leaving it would have fed every later epic instructions that no longer match what a record contains — the harness had to learn the new vocabulary in the same release that introduced it.
- **D10's and D11's promised wording amendments are still unapplied on the live issues** (#794): both were recorded as `pending` BLOCKERs under "Resolve before approval" and the epic put holding approval on a pending amendment out of scope, so approval proceeded with them open. The shipped code honours both decisions — the stage edits no epic or story text (G17, G25) and a revision keeps its approved format (G11) — but #791 criterion 4 still reads "never edits the epic issue or a story issue" and #787's second assumption still reads "the new format applies to records drafted after the release". The exact replacement wording is in D10 and D11; applying it is the lead's outstanding action.
